# 手册数据维护

手册的每一页都不是写死的文章，而是由数据生成的。你能改的就是这些数据。

不需要写代码，不需要装软件，有个浏览器就够了。

## 一、打开编辑器

编辑器和手册在同一个站点上，地址是站点地址后面加 `editor/`：

- 线上：`https://zhuty18.github.io/goodsbar-tutorial/editor/`
- 本地：`http://localhost:4321/goodsbar-tutorial/editor/`

它不在导航栏里，是给维护者用的内部页面。

## 二、怎么改

左边是七类数据：

| 类别 | 是什么 |
| --- | --- |
| 界面 | 软件里的页面 |
| 原子操作 | 一次点击或输入，绑定在某个界面上 |
| 行为 | 一个界面里的一组操作，有先后顺序 |
| 功能 | 一串行为，对应一个使用需求（也就是手册的一页） |
| 概念 | 需要单独解释的术语 |
| 标签 | 给行为打的标记，比如「需要权限」 |
| 分类 | 功能的归类，卡片角标显示它的第一个字 |

操作方式：

- 左侧列表按 id 排序；点分组标题可以折叠/展开，当前正在编辑的那条所在的分组会自动展开。
- 「+」新建，表单右上角「删除」移除。
- 引用别的东西（比如给一个行为挑原子操作）用勾选或下拉，不用手动输 id。
- 改了任何东西，右上角会提示「有未导出的改动」。

导出前先看一眼右侧表单有没有红字提示——有的话说明引用没填全。

## 三、导出

点右上角「导出打包文件」，浏览器会下载 `goodsbar-content.json`。

这个文件是**你当前看到的全部数据**，不用只挑改过的那几条——合并时只按 id 覆盖，你没动的内容不会被改掉，维护者也会人力盯梢。所以放心地整份导出。

## 四、把文件交回来

### 会用 GitHub

到 <https://github.com/zhuty18/goodsbar-tutorial/issues> 新建一个 issue：

1. 标题写清楚改了什么，例如「补充：创建多规格制品的完整流程」或「修正：设置tag的完整流程」
2. 把 `goodsbar-content.json` 拖进输入框
3. 提交 issue

**请不要开 Pull Request。** 数据结构还在调整，随时可能有大规模变动，直接改文件的 PR 很容易冲突，反而不好合并。issue 里的数据包由维护者统一处理。

### 不会用 GitHub

加 QQ：**3440950898**（兔子草），把 `goodsbar-content.json` 发过去就行，顺便说一句改了哪些地方。

## 五、几条约定

- **不要修改已建立条目的 id。** id 是各处引用的目标，改了会断。想换显示的文字，改「名称」「标题」这类字段。
- **拿不准就留空或写备注。** 合并前维护者会过一遍，不会因为一处没填全就丢东西。

## 六、署名

目前手册中还没有署名字段，署名仅出现在commit message里。

通过 GitHub 提交的数据包默认用 GitHub 账户和邮箱署名，也可在提交的issue中选择自己想要的署名。

通过 QQ 提交的数据包默认标注 QQ 号作为署名。
